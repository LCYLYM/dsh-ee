## M1 示例公司与一键导入 / 清除

现状：`server/internal/api/demo_content.go` + `demo.go` 能导入两个知识库、一个演示差旅系统（`/demo/travel/*`）、一个技能、一个提示词、两个微应用和两个演示员工，入口在 `/go` 部署清单的「示例内容」一步（`web/src/components/demo-import.tsx`）。

### 任务

1. **示例公司设定**：「星河科技」，约 200 人，部门有研发、销售、财务、人力、IT、法务。写一份设定文档 `docs/demo-company.md`（组织架构、人物、各部门在用的系统），后面所有示例内容都按它写，保证前后一致。
2. **演示员工**：扩到 8～10 人，覆盖每个部门，有部门负责人；其中一两人预置自己搭建的「自己用」应用（依赖 M4，M4 完成前先跳过这一项）。
3. **知识库**：每个部门 1～2 个库，文档写得像真的（制度、手册、FAQ、产品资料、IT 排障手册）。现有的差旅制度和员工手册保留并补充。
4. **演示业务系统**：沿用 `/demo/travel/*` 的做法（内存数据、`X-Demo-Key`、OpenAPI 连接走回环地址），新增：
   - `/demo/crm/*`：客户、合同、拜访记录、续约日期，约 50 个客户，有几个续约风险高的客户；
   - `/demo/itsm/*`：工单（可以新建，写操作走审批卡）、常见故障分类；
   - 差旅系统补数据：几十张报销单，有不同状态和几个异常单据。
   数据要有趋势和异常值，看起来才像真的。重启后恢复初始数据，这样示例环境不会被试坏。
5. **30 天模拟使用数据**：导入时写入近 30 天的模型调用、能力安装和应用运行记录，让管理总览、运营数据页一打开就有曲线。写入时要标记为示例数据，以便清除。
6. **一键导入的入口**：
   - 保留 `/go` 部署清单里的入口；
   - 首次启动后的欢迎页加「导入示例公司，马上体验」，作为最显眼的选项；
   - 导入完成后显示下一步：用哪个演示员工登录、怎么在 DSH 里接入、先试哪个应用。
7. **一键清除示例数据**：试用完要转正式使用时，能把示例的知识库、连接、应用、员工、模拟统计全部删掉，不影响用户自己建的内容。导入时记录每一条示例数据的 ID，清除时只删这些。
8. **离线可用**：示例内容全部内嵌在二进制里，离线安装包导入同样能用。

### 完成标准

- 全新部署 → 欢迎页点「导入示例公司」→ 一分钟内完成 → 用演示员工登录，网页上能看到全部示例内容和有曲线的统计页。
- 重复导入是幂等的；清除后再导入，结果和第一次一样。
- 清除后，用户自己创建的内容一条不少（e2e 覆盖）。

## M2 工作台组件升级

现状：`dsh-plugin/src/workbench-view.ts` 支持 `metric`、`table`、`form`、`actions`、`markdown`、`board`、`kb_scope`。

### 任务

1. **`chart` 图表**：折线、柱状、饼图，数据源和 `metric` 一样，只能用只读工具；配置项有 x 字段、y 字段（可多个）、类型。在插件里画，不引入大型图表库（SVG 自己画或选体积很小的库）。
2. **`checklist` 清单**：管理员定义条目，或从只读工具取；员工可以勾选，勾选状态按会话保存；AI 能通过看板工具更新清单状态。
3. **详情卡**：`table` 的行可以展开成详情卡，显示配置好的字段；行按钮保持现有行为（把一段话发给 AI）。
4. **四种状态**：加载中（骨架屏）、空状态（一句说明 + 一个建议操作）、无权限（说明缺什么权限，链接到 M7 的申请）、出错（错误原因 + 重试）。现有组件全部补齐。
5. **视觉细节**：组件分组标题、间距、数字格式化与变化动画，跟随 DSH 的亮色 / 暗色主题。
6. 网页端编辑器同步支持新组件的配置和保存时校验（只读工具校验沿用现有逻辑）。

### 完成标准

- 每种组件的每种状态都有截图（亮色、暗色各一张），放进 `docs/workbench-verify.md` 对照。
- 保存配置时，图表和清单的数据源不是只读工具会被拒绝（服务端测试覆盖）。

## M4 导航重组与「自己用」免审核

### 任务

1. **导航按「用 / 造 / 管」重组**（菜单由后端决定，所以改的是默认菜单数据和迁移）：
   - 用：企业应用（原能力中心只留应用）、知识问答、我的工作台；
   - 造：新建应用、我的应用、从样板复制、原料（我能用的知识库、连接、技能、提示词、插件）；
   - 管：现有的管理页面，只对管理员显示。
   管理员改过的菜单不覆盖（沿用「还是默认值时才更新」的规则）。
2. **能力中心对员工只展示应用**；技能、提示词放进应用详情和「造 → 原料」；插件只在「造」的高级选项和管理里出现。旧路由 `/hub`、`/market` 继续跳转。
3. **「自己用」免审核**：在 `handleHubCreate` / `initialStatus` 里，当可用范围只有本人（`Scope.Users = [自己]`，不含部门、角色、全员）时直接发布，下发方式固定为「自选」。
4. **改范围即提交审核**：「自己用」的应用把范围改大时，新范围进入审核；审核通过前，作者自己照常能用。
5. 网页端 `/workbench` 的「我的微应用」换成真实数据（现在是模拟数据）。

### 完成标准

- 服务端测试：范围只有本人 → published；范围加了任何部门或角色 → pending；「自己用」的应用别人在 DSH 里看不到。
- 员工账号登录，首页看不到任何管理入口，也看不到「插件」这个词，除非进入「造」的高级选项。

## M5 应用编辑器

### 任务

1. **从样板复制**：样板（M3）和公司里已发布的应用都可以「复制为我的应用」，复制后是「自己用」。
2. **实时预览**：编辑器左边配置、右边预览工作台，用演示数据或真实的只读工具取数（以当前登录员工的身份）。网页上的预览和 DSH 里的工作台共用一套渲染代码，避免两边不一致（把 `workbench-view.ts` 的渲染抽成可在网页端复用的模块）。
3. **原料一键生成应用草稿**：
   - 知识库页：「用这个库做问答应用」，模型读几篇文档后拟出说明和示例问题；
   - 连接页：「用这个连接做应用」，按工具清单建议面板（列表工具 → 表格，数字工具 → 指标卡，写工具 → 快捷按钮）。
   生成的都是「自己用」的草稿，作者改完再分享。
4. **原料被谁用**：知识库、连接、技能、提示词的详情页显示「被哪些应用用了」。
5. **应用导入导出**：一个应用导出成一个文件（应用定义 + 工作台配置 + 依赖清单 + 可选的知识文档），可以导入到另一个 dsh-ee。依赖的连接在导入后需要管理员重新配置凭据（导出文件里不带任何凭据）。这是社区投稿模板的格式。

### 完成标准

- 从样板复制 → 改一个组件 → 预览立刻变化 → 保存 → 在 DSH 里打开，和预览一致。
- 导出的文件里搜不到任何密钥、令牌（测试覆盖）。

## M6 DSH 首屏启动台与「工作台」系统应用

现状：接入插件已在 `conversation.hero.options` 注册了一个「企业应用」下拉菜单（`dsh-plugin/src/apps-view.ts` 的 `heroAppsMenu`，最多 8 个）。

### 任务

1. **首屏启动台**：把下拉菜单改成直接铺开的卡片区——问候语、4～8 个应用卡片（我常用 → 部门推荐 → 全公司热门）、2～3 个轮换的示例问题（点了直接打开对应应用并发送）、「需要你处理」一行。新上线的应用带「新」标记。
2. **应用首页小卡片**：应用编辑器里可以把 0～2 个只读组件勾选为「显示在首页」，比如「待补票据 2 张」。首屏「需要你处理」和工作台系统应用都从这里取数。
3. **「工作台」系统应用**：仿照 `kb-qa` 由代码生成。右侧面板是我的待办（汇总首页小卡片）、我的应用（可固定）、本月用量与额度、新上线的应用、最近会话；左边对话是「总助理」，会把问题引到合适的应用。
4. **降级**：hero slot 不可用或宿主版本不支持时，退回现有的侧栏入口，不报错。

### 完成标准

- Mac 上的 DSH Desktop 新建对话，首屏能看到启动台；点示例问题能直接进入对应应用。
- 首页小卡片的数据和对应应用工作台里的数据一致。

## M7 应用详情：依赖与权限状态，一键申请

### 任务

1. 应用详情页（网页端和 DSH 里）列出依赖的知识库、连接工具、技能，并显示当前员工的状态：可用 / 缺权限。
2. **一键申请**：缺权限时点「申请」，生成一条申请，写明是为了哪个应用。审批人是对应连接或知识库的维护者，没有维护者时给管理员。
3. **统一的「我的申请」和「待我审批」**：把现有按资产类型分开的审核队列，在员工视角合并成一个列表（管理员的审核队列保留原样）。
4. 申请通过后，员工的 DSH 自动刷新可用工具（沿用 `tools/list_changed`）。

### 完成标准

- 缺 CRM 权限的员工打开客户拜访简报，能看到缺什么，点申请 → 管理员通过 → 员工不用重启 DSH 就能用。

## M8 反馈与使用数据

### 任务

1. **先做一个小验证**：DSH 有没有可以给每条回答加按钮的 slot。如果有，就用它；没有的话，就在看板上加「这次结果有帮助吗 👍👎」。
2. 记录每次评价，关联到应用、会话和对应的那次回答。
3. **应用详情里给作者看的数据**：运行次数、使用人数、好评率、近 30 天趋势。
4. **答不上来的问题**：自动收集三类信号——知识库检索结果为空、工具调用报错、被点了 👎——按相似问题合并，列成作者的待办，例如「12 人问过『年假能不能跨年』，知识库里没有答案」。
5. 隐私：作者只能看到问题文本和次数，看不到是谁问的；管理员看到的范围和现有审计一致。

### 完成标准

- 在示例环境里点几次 👎、问几个知识库里没有的问题，作者的待办里能看到合并后的结果。

## M9 `/ee-save`：把对话沉淀成能力

### 任务

1. 在接入插件里注册 `/ee-save`：读取当前会话，让模型提炼成提示词、技能或应用草稿（让员工选类型，或者由模型建议）。
2. 草稿存成「自己用」，附上原始对话摘要作为说明；返回一个网页链接，员工可以在编辑器里继续改。
3. 员工在网页上把范围改大时走审核（M4）。
4. 员工工作台显示「我分享的能力被多少人用了多少次」。
5. 只提交员工本人这段对话的内容；提交前在 DSH 里提示「会把这段对话的摘要发到 dsh-ee」。

### 完成标准

- 在 DSH 里聊完一段 → `/ee-save` → 网页上出现草稿 → 自己的 DSH 里能用 `/名字` 调出来。

## M10 收尾功能

1. **OIDC 登录**：和 LDAP / AD 并列，支持常见的 IdP（Keycloak、Authing、Azure AD），声明 → 角色映射沿用 LDAP 组映射的做法。
2. **月度 AI 落地报告**：管理总览加「导出月度报告」，内容是活跃率、各应用使用量、热门问题、好评率、估算节省的工时（估算方法写清楚，管理员可以调参数）。导出为可打印的网页，浏览器另存 PDF 即可，不引入 PDF 库。
