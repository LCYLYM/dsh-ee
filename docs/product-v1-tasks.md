## M1 示例公司与一键导入 / 清除

现状：`server/internal/api/demo_content.go` + `demo.go` 能导入两个知识库、一个演示差旅系统（`/demo/travel/*`）、一个技能、一个提示词、两个微应用和两个演示员工，入口在 `/go` 部署清单的「示例内容」一步（`web/src/components/demo-import.tsx`）。

### 任务

1. **示例公司设定**：「星河科技」，约 200 人，部门有研发、销售、财务、人力、IT、法务。写一份设定文档 `docs/demo-company.md`（组织架构、人物、各部门在用的系统），后面所有示例内容都按它写，保证前后一致。
2. **演示员工**：扩到 8～10 人，覆盖每个部门，有部门负责人；其中一两人预置自己搭建的「自己用」应用（依赖 M4，M4 完成前先跳过这一项）。
3. **知识库**：每个部门 1～2 个库，文档写得像真的（制度、手册、FAQ、产品资料、IT 排障手册）。现有的差旅制度和员工手册保留并补充。
4. **演示业务系统**：沿用 `/demo/travel/*` 的做法（内存数据、`X-Demo-Key`、OpenAPI 连接走回环地址），新增：
   - `/demo/crm/*`：客户、合同、拜访记录、续约日期，约 50 个客户，有几个续约风险高的客户；
   - `/demo/itsm/*`：工单（可以新建，写操作走审批卡）、常见故障分类；
   - 差旅系统补数据：几十张报销单，有不同状态和几个异常单据。
   数据要有趋势和异常值，看起来才像真的。重启后恢复初始数据，这样示例环境不会被试坏。
5. **30 天模拟使用数据**：导入时写入近 30 天的模型调用、能力安装和应用运行记录，让管理总览、运营数据页一打开就有曲线。写入时要标记为示例数据，以便清除。
6. **一键导入的入口**：
   - 保留 `/go` 部署清单里的入口；
   - 首次启动后的欢迎页加「导入示例公司，马上体验」，作为最显眼的选项；
   - 导入完成后显示下一步：用哪个演示员工登录、怎么在 DSH 里接入、先试哪个应用。
7. **一键清除示例数据**：试用完要转正式使用时，能把示例的知识库、连接、应用、员工、模拟统计全部删掉，不影响用户自己建的内容。导入时记录每一条示例数据的 ID，清除时只删这些。
8. **离线可用**：示例内容全部内嵌在二进制里，离线安装包导入同样能用。

### 完成标准

- 全新部署 → 欢迎页点「导入示例公司」→ 一分钟内完成 → 用演示员工登录，网页上能看到全部示例内容和有曲线的统计页。
- 重复导入是幂等的；清除后再导入，结果和第一次一样。
- 清除后，用户自己创建的内容一条不少（e2e 覆盖）。

### 完成情况（2026-11-07）

全部完成。设定见 [demo-company.md](./demo-company.md)。

- 本地实测：部署清单点「导入示例公司」约 3～4 秒完成（e2e `18-demo-company`）；用演示员工周航登录能看到企业应用、自己用的「我的客户周报」和各部门知识库；运营数据、月度报告有 30 天曲线。
- 重复导入幂等、清除后再导入和第一次一样、清除后用户自己的账号 / 提示词 / 知识库都在：`TestDemoImport` 与 e2e 覆盖。
- 和计划的差别：
  - 「能力安装」的模拟数据用的是演示员工启用「周报」提示词的记录（示例里没有插件包，不造 npm 下载记录）。

## M2 工作台组件升级

现状：`dsh-plugin/src/workbench-view.ts` 支持 `metric`、`table`、`form`、`actions`、`markdown`、`board`、`kb_scope`。

### 任务

1. **`chart` 图表**：折线、柱状、饼图，数据源和 `metric` 一样，只能用只读工具；配置项有 x 字段、y 字段（可多个）、类型。在插件里画，不引入大型图表库（SVG 自己画或选体积很小的库）。
2. **`checklist` 清单**：管理员定义条目，或从只读工具取；员工可以勾选，勾选状态按会话保存；AI 能通过看板工具更新清单状态。
3. **详情卡**：`table` 的行可以展开成详情卡，显示配置好的字段；行按钮保持现有行为（把一段话发给 AI）。
4. **四种状态**：加载中（骨架屏）、空状态（一句说明 + 一个建议操作）、无权限（说明缺什么权限，链接到 M7 的申请）、出错（错误原因 + 重试）。现有组件全部补齐。
5. **视觉细节**：组件分组标题、间距、数字格式化与变化动画，跟随 DSH 的亮色 / 暗色主题。
6. 网页端编辑器同步支持新组件的配置和保存时校验（只读工具校验沿用现有逻辑）。

### 完成标准

- 每种组件的每种状态都有截图（亮色、暗色各一张），放进 `docs/workbench-verify.md` 对照。
- 保存配置时，图表和清单的数据源不是只读工具会被拒绝（服务端测试覆盖）。

### 完成情况（2026-11-07）

代码完成并已在真实 `dsh web` 验证（`e2e/dsh/scenarios/run-m2.mjs`，覆盖下表 M2-1～M2-9 的等价检查，见 [workbench-verify.md §6](./workbench-verify.md)）；Desktop 客户端与暗色主题的目视核对待补。

- 新组件：`chart`（line / bar / pie，SVG 自己画）、`checklist`（配置条目或只读工具取；勾选按会话存在本机；AI 用 `ee_workbench` 的 `action: "checklist"` 更新）、`heading`（分组标题）、`table.detail`（详情卡）、`metric.delta_field` 与 `compact` 格式、`empty`（空状态的说明与建议操作）。
- 四种状态：骨架屏、空状态、无权限（链接到 dsh-ee 的 `/connections/<标识>`，M7 做好后那里就是申请入口）、出错（原因 + 重试），所有带数据源的组件都有。
- 截图：亮色、暗色各一张「状态图鉴」，用插件真实的渲染函数画出（`docs/images/workbench-states/`）；DSH 里的真机截图待验证时补。
- 和计划的差别：网页端编辑器仍是 JSON 编辑 + 结构预览，「插入示例」里每种新组件都有一份；可视化编辑和与插件共用渲染的实时预览放在 M5。
- 已知限制：多序列图表共用一个纵轴，数量级差很多的序列（金额和单数）放在一张图里，小的那条会贴着底。

## M4 导航重组与「自己用」免审核

### 任务

1. **导航按「用 / 造 / 管」重组**（菜单由后端决定，所以改的是默认菜单数据和迁移）：
   - 用：企业应用（原能力中心只留应用）、知识问答、我的工作台；
   - 造：新建应用、我的应用、从样板复制、原料（我能用的知识库、连接、技能、提示词、插件）；
   - 管：现有的管理页面，只对管理员显示。
   管理员改过的菜单不覆盖（沿用「还是默认值时才更新」的规则）。
2. **能力中心对员工只展示应用**；技能、提示词放进应用详情和「造 → 原料」；插件只在「造」的高级选项和管理里出现。旧路由 `/hub`、`/market` 继续跳转。
3. **「自己用」免审核**：在 `handleHubCreate` / `initialStatus` 里，当可用范围只有本人（`Scope.Users = [自己]`，不含部门、角色、全员）时直接发布，下发方式固定为「自选」。
4. **改范围即提交审核**：「自己用」的应用把范围改大时，新范围进入审核；审核通过前，作者自己照常能用。
5. 网页端 `/workbench` 的「我的微应用」换成真实数据（现在是模拟数据）。

### 完成标准

- 服务端测试：范围只有本人 → published；范围加了任何部门或角色 → pending；「自己用」的应用别人在 DSH 里看不到。

## M13 应用自带数据

### 任务

5. 数据的安全网：作者和应用管理员可以导出 CSV；删除应用后数据保留 30 天，可以恢复。

7. 员工侧 `ee_app` 工具：只能新建 / 修改自己的「自己用」应用（含表结构和工作台）；分享仍在网页上走审核（已定放在这里，M9 复用它的草稿流程）。
8. 示例公司：加一个带自带数据的样板（团建报名或设备借用登记，`shared` 模式）；新人入职的清单改为自带表（`own`）；一键清除时一起清掉。

### 完成标准

- 在 DSH 里一句话让 AI 做出一个报名应用，立刻能填、能看统计；另一个员工按 `own` 模式只看到自己的行（e2e + 真实 DSH 场景）。
- 改字段不丢数据；超过行数上限给出明确提示；删除应用后 30 天内能恢复（Go 测试覆盖）。

### 完成情况（2026-11-07）

代码完成，等 Mac 真机验证（清单见 [workbench-verify.md §8](./workbench-verify.md)）。

- 服务端：`server/internal/api/app_data.go`，存储 `store/app_rows.go`（迁移 0016）。网页接口 `/api/apps/{slug}/data[/{table}[/{id}|/export]]`；DSH 里是 `/mcp` 上的 `app__rows`（只读，支持筛选、搜索、排序、`group_by` 计数）和 `app__write`（insert / update / delete）。能用这个应用的人就能用它的数据，不要求在 DSH 里启用；作者和有「管理能力」权限的人看全部、改任何行。
- 工作台：服务端在给 DSH 的目录里把 `{"table": …}` 换成 `app__rows` 调用，插件取数逻辑不用改；表单 `submit.table` 由插件经 `app__write` 插入，成功后刷新读这张表的组件；`submit` 没写 `fields` 时按表生成（money → number，bool → 是 / 否）。
- 删除：网页上确认框；模型那边复用 Agent 的确认码（先拿预览、带 `confirm` 再执行），插件按 `_meta` 弹审批框。行和应用都是软删除，每天清一次超过 30 天的。
- 和计划的差别：
  - **没有单独的 `ee_app` 工具**：Agent 工具是按路由一一对应的，`POST /api/hub` 已经是 `ee_hub.create`。改为给它加 `for_me`（范围只有本人 → 免审核、马上能用），并把 `tables`、`workbench`、`connections`、`knowledge`、`icon` 写进参数说明。效果一样，少一个工具。
  - **行数上限还不能调**：固定每个应用 1 万行、每行 16 KB。
  - **删除后的恢复还没有界面**：数据保留 30 天，但目前只能在数据库里把 `deleted_at` 清空。
  - **DSH 工作台里还不能直接编辑行**：表格只显示，改和删交给 AI（会确认）；网页的应用详情里能新增和删除。行内编辑放到 M14 的网页版一起做。
  - 「各自填写」的表，统计（`group_by`）也只算员工自己能看到的行，不会把别人的数据按组漏出来；组织者（作者）看到全部。
  - 新人入职清单改成自带表放到 M3 重做样板时一起做；示例公司先加了「团建报名」（各自填写 + 作者发布两张表，不是计划里写的 `shared`，更贴近报名场景）。
- 踩到的坑：TiDB 里「按 JSON 值排序 + 第二个排序键 + LIMIT」会排错（没有值的行跑到最前），所以按字段类型先转换（数字 `CAST … AS DOUBLE`，其余转成文字）再排，没有值的行总在最后。
- 测试：Go `TestAppData`、`TestAgentTools`（`for_me`）、`TestDemoImport`；插件 `insertFormRow`；e2e `20-app-data`。

### 完成情况（2026-11-07）

完成（真机核对清单见 [workbench-verify.md §10](./workbench-verify.md)）。

- 新包 `server/internal/datahub`：连接、自动建只读账号、建表 / 替换 / 追加、执行查询（`max_execution_time` 10 秒、最多 1000 行）、SQL 检查与 `:参数` 绑定、CSV / xlsx 解析与类型推断（xlsx 自己读 zip + XML，不引入新依赖）。
- 说明存在主库（迁移 0017：`data_tables`、`data_sets`），数据在单独的库。API 在 `server/internal/api/datahub.go`；系统连接 `data` 的工具 `data__dataset`；工作台数据源 `{"dataset": …}`（目录里换成 `data__dataset` 调用，网页版按配置执行）；编辑器里列出员工能用的数据集。
- 网页：「企业连接」页的「数据中台」页签（上传、预览、删除；数据集的 SQL、参数、范围、试运行）。没有新加菜单项，老部署的菜单不用迁移。
- 部署：`DSH_EE_DATA_DSN` 默认由 `DSH_EE_DSN` 推出 `<库名>_data`，`off` 关闭；`DSH_EE_DATA_READ_DSN` 可选。开不起来时只关这一块，页面上说明原因。
- 示例公司：「客户主数据」「人员」两张表，「客户主数据」「我负责的客户」（`:me_name`）「本部门同事」（`:me_department`）三个数据集；周航的「我的客户周报」用数据集做了工作台并开了网页版；清除时删表删数据集。
- 和计划的差别：
  - **只读不靠事务**：TiDB 的 `START TRANSACTION READ ONLY` 只是空实现，所以靠只读账号；建不了只读账号时可以上传，但数据集不能查，页面上给出要配的环境变量；
  - CSV 只认 UTF-8（GBK 的提示另存为「CSV UTF-8」或直接传 .xlsx）；老的 .xls 不支持；
  - 表本身没有可见范围：员工只能经数据集用数据，范围设在数据集上（v1.1 的 `data__query` 再给表加范围）；
  - `ref` 字段（应用自带表引用数据集）和升格放到 v1.1，见 §10.9 第 3 项。
- 测试：`internal/datahub` 单测；Go `TestDataHub`、`TestDemoDataHub`；e2e `22-data-hub`。
