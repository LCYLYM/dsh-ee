# DSH 深度联动：产品规划（v0.3 草案，2026-10-31）

> 配套：技术规划与验证方式见 [agent-connect-tech.md](agent-connect-tech.md)；前一阶段的能力中心见 [capability-hub.md](capability-hub.md)。
>
> 已定：① 「企业二次分发的令牌」= 企业买来的模型额度，由 dsh-ee 按人 / 团队 / 机器人再发令牌；② 管理员经 Agent 操作需要单独开启「管理模式」，限时有效；③ 改密码、离线包导入导出、重置菜单、LDAP 绑定密码不开放给 Agent。

## 1. 要解决的问题

能力中心已经把技能、提示词、企业连接、插件和模型下发到员工的 DSH，但还有三处断点：

| 断点 | 现状 | 后果 |
|---|---|---|
| 令牌 | 员工要在网页上生成 `ee_npm_` 令牌，由 `setup.sh` 明文写进 `$DSH_HOME/.env`；模型另有一套 `sk-ee` key | 两套令牌说不清；令牌明文落盘；吊销后 DSH 只会报 401，员工不知道怎么办 |
| 分发 | 额度只能按账号设，团队共用、CI 机器人只能借某个人的账号 | 二次分发不可控，用量算不清 |
| 操作 | dsh-ee 的所有功能只能在网页上点 | DSH 里的 Agent 帮不上忙；新员工接入、管理员初始化都要看文档一步步点 |

## 2. 目标与非目标

**目标**

1. **一个令牌通全部**：员工在 DSH 里登录一次企业账号，就能用企业模型额度、npm 源、技能、提示词、企业连接、插件，以及 dsh-ee 的全部自助功能。令牌不需要复制粘贴，也不写进 `.env` 或任何配置文件，而是由 DSH 的凭据库保管（本机私有文件，仅本人可读）。
2. **二次分发**：管理员可以给个人、团队、机器人发令牌，各自设额度、可用模型、有效期、能力范围，随时吊销，用量分开统计。
3. **Agent 能做 dsh-ee 的全部工作**：普通员工能做的、管理员能做的，在 DSH 里用自然语言都能完成，权限与网页完全一致，危险操作必须人确认，并且都有审计。
4. **Agent 当向导**：指导员工完成接入、排查故障、找到并启用合适的能力、把自己的成果分享出去；指导管理员从零完成一套部署。

**非目标（本期不做）**

- 企业定制版 DSH 本体（品牌、预装）：仍暂缓，本期只做插件。
- 知识库。
- 给外部合作方（非企业员工）发令牌：机器人令牌只属于企业内部服务。
- Agent 绕过网页审批：审核、授权这些需要人判断的环节，Agent 只做准备和建议，最后一步仍由有权限的人确认。

## 3. 角色

| 角色 | 典型诉求 |
|---|---|
| 员工 | 「帮我接好公司的 DSH」「我这个月还剩多少额度」「有没有查 Jira 的能力，帮我开一下」「把刚才这个提示词分享给组里」 |
| 部门负责人 / 能力维护者 | 「给我们组发一个共用令牌，每月 500 万 token」「把这个技能只开放给研发部」 |
| 管理员 | 「接入 DeepSeek，给研发部每人 200 元额度」「审核队列里有什么，帮我看看这个插件有没有风险」「上周谁调用了财务系统」 |
| 机器人 / CI | 用团队令牌跑自动化任务，额度独立，不挂在某个人名下 |

## 4. 功能一：统一接入令牌

### 4.1 令牌是什么

一种令牌（前缀 `ee_at_`），带这些属性：

| 属性 | 说明 |
|---|---|
| 持有者 | 个人账号，或机器人账号（团队 / 服务用） |
| 能力范围 | 勾选：模型、安装插件、发布插件、技能与提示词、企业连接、Agent 自助操作、Agent 管理操作 |
| 额度 | 每月 token 上限（可空 = 只受账号额度约束） |
| 可用模型 | 可空 = 账号允许的全部模型 |
| 有效期 | 可空 = 长期；登录产生的令牌默认 90 天，使用时自动续期 |
| 来源 | 在 DSH 里登录 / 网页手动生成 / 管理员下发 |
| 设备 | 登录产生的令牌记录设备名、系统、DSH 版本，方便员工认出「这是我哪台电脑」 |

**规则**

- 令牌能做的事 = 持有者账号的权限 ∩ 令牌的能力范围。令牌永远不会比账号本身权限大。
- 实际额度 = min(令牌剩余额度, 账号剩余额度)。两者谁先用完都停。
- 「Agent 管理操作」范围默认不勾，而且即使勾了，也只有在「管理模式」开启期间才生效（见 §6.3）。
- 老令牌照常可用：`ee_npm_`（只读 / 可发布）和 `sk-ee` key 自动视为固定范围的令牌，页面上一起列出，标「旧版」。不强制迁移。

### 4.2 员工接入（目标体验）

```
员工：运行一行命令（setup.sh，不用事先生成令牌）
  ↓
终端显示确认码 KQ7M-4XPD，并自动打开浏览器（打不开时显示链接）
  ↓
浏览器打开 dsh-ee：
  ┌──────────────────────────────────────────┐
  │ 授权 DSH 访问你的企业账号                 │
  │ 设备：张三的 MacBook · macOS 15 · DSH 0.2 │
  │ 确认码：KQ7M-4XPD（与终端中显示的一致）  │
  │ 将获得：模型 · 安装插件 · 技能与提示词 ·   │
  │         企业连接 · Agent 自助操作          │
  │              [拒绝]  [授权]                │
  └──────────────────────────────────────────┘
  ↓
终端显示「已登录 zhangsan（研发效能部）」→ 写好 .npmrc、装好接入插件
  ↓
启动 DSH，模型、技能、连接直接可用；对话框输入 /ee-status 可查看登录状态
```

以后令牌失效（被吊销、过期）时，在 DSH 对话框输入 `/ee-login`，DSH 显示确认码与链接，浏览器确认后无需重启 DSH。

- 没登录 dsh-ee 网页时，确认页先走正常登录（含 LDAP）。
- DSH 0.2.1-rc.5 实测没有通用授权设置页或 notice 展示入口（S1），所以登录入口由 setup 脚本和接入插件的 `/ee-login` 命令提供，不依赖 DSH 设置页。
- 令牌由 DSH 的凭据库保管（`$DSH_HOME/.credentials.yaml`，权限 0600），配置文件里只有名字。注意它和 `.npmrc` 一样是本机私有文件，不是加密存储：防的是「令牌散落在 .env、项目目录、聊天记录里」，不防本机同一用户下的进程。
- 登录入口：首次接入在 `setup.sh` 的终端里完成（打开浏览器确认）；之后在 DSH 对话框输入 `/ee-login` 重新登录（详见 [阶段 A 实施规划](agent-connect-phase-a.md)）。
- 吊销或过期后，模型请求的报错文案直接写明「企业账号登录已失效，在对话框输入 /ee-login 重新登录」，而不是一串 401。
- 老方式（手动生成令牌写 `.env`）继续支持，供无浏览器的服务器、CI 使用。

### 4.3 网页：「我的令牌」页

把现在的「我的 Key」与接入指南里的 npm 令牌合并为一页：

- 列表：名称、来源（DSH 登录 / 手动 / 管理员下发 / 旧版）、设备、能力范围、本月用量 / 额度、最后使用时间与 IP、状态。
- 操作：生成令牌（选能力范围、额度、有效期）、吊销、开启 / 关闭管理模式（有管理权限的人才看到）。
- 设备登录的令牌被吊销时，提示「对应的 DSH 下次请求会要求重新登录」。

### 4.4 网页：二次分发（管理侧）

「令牌管理」页（替代现在的「Key 管理」）：

- 按人、按部门、按机器人账号筛选所有令牌；批量吊销某人 / 某设备 / 某部门的令牌。
- **机器人账号**：新建时选所属部门和负责人，可分配角色和每月额度；只能用令牌访问，不能登录网页。用于团队共用和 CI。
- **给团队发令牌** = 建一个机器人账号 + 给它发令牌，令牌明文只显示一次，可以复制、下载成 `.env`。
- 负责人（部门管理员）可以管理本部门机器人账号的令牌，前提是拥有新增的权限点「本部门令牌管理」。

### 4.5 运营统计

- 用量按「令牌」细分：同一个人的笔记本、台式机、CI 各用了多少。
- 机器人账号的用量单独成行，不再混在个人头上。

## 5. 功能二：DSH 里的 Agent 操作 dsh-ee

### 5.1 体验原则

1. **网页能做的，Agent 都能做**；网页不能让你做的，Agent 也不能做。
2. **读随便问，写先说清楚**：查询类直接执行；会改数据的操作，Agent 先说清楚要做什么，DSH 弹审批框，你同意才执行。
3. **危险操作两步走**：删除、吊销、改权限、改系统设置这类操作，dsh-ee 先返回「将要发生什么」的预览（影响到谁、多少条），确认后才真正执行，并且确认只对这一次有效。
4. **所有操作有来历**：审计日志标注「经 Agent」，以及哪个令牌、哪台设备。
5. **Agent 只看到自己能用的工具**：员工看不到管理工具；角色或令牌范围一变，DSH 里的工具立刻更新。

### 5.2 员工能用 Agent 做的事

| 领域 | 能做的事 | 类别 |
|---|---|---|
| 账号与额度 | 查本月额度、用量趋势、各令牌用量 | 只读 |
| 令牌 | 列出、生成、吊销自己的令牌 | 写 / 吊销为危险 |
| 能力中心 | 搜索能力（按关键词、类型、部门热度）、看详情、启用 / 停用 | 读 / 写 |
| 分享 | 把当前对话里写好的技能、提示词、微应用直接提交到能力中心（自动走审核）；修改自己的能力、提交新版本 | 写 |
| 插件 | 把本地项目打包上传为插件、申请引入外部 npm 包、查看审核进度 | 写 |
| 企业连接 | 查看自己能用哪些系统和工具；申请使用某个连接（生成申请，通知管理员） | 读 / 写 |
| 使用记录 | 查看自己的模型调用、连接调用记录 | 只读 |
| 接入诊断 | 「为什么我的 DSH 连不上 / 没有某个技能」→ 自检并给出修复步骤 | 只读 + 本机修复 |

### 5.3 管理员能用 Agent 做的事（需管理模式）

| 领域 | 能做的事 |
|---|---|
| 用户与组织 | 列表、搜索、新建、停用、改部门、设角色、建机器人账号 |
| 角色与权限 | 新建 / 修改角色、调整权限点 |
| 额度 | 按人、按部门批量设置额度 |
| 令牌 | 查看、下发、吊销任何人的令牌 |
| 模型 | 接入供应商、检测连通、上架模型、设默认模型 |
| 审核 | 查看审核队列；Agent 读包内容 / 技能正文，给出风险摘要；**通过或驳回需要管理员在审批框确认** |
| 能力中心 | 修改任何能力的范围与下发方式；插件策略（自动安装、可用范围） |
| 企业连接 | 登记 MCP / 导入 OpenAPI、试连、开关工具、按角色授权、查调用日志 |
| npm 源与上游 | 查看源状态、同步上游、检查更新、查看任务 |
| 系统设置 | 修改站点设置、接入插件设置、发布接入插件、LDAP 连接与同步（不含绑定密码） |
| 审计与统计 | 按人 / 动作 / 时间查询审计日志；运营统计问答（「上周哪个部门用量涨得最多」） |
| 菜单 | 调整菜单名称、顺序、显隐（不含「重置菜单」） |

### 5.4 不开放给 Agent 的功能

| 功能 | 原因 |
|---|---|
| 改自己的密码、改他人密码 | 凭据只在网页上由本人操作 |
| 离线包导出 / 导入 | 涉及大文件与整库变更，必须人工在网页上做 |
| 重置菜单 | 全局破坏性操作，网页上也有二次确认 |
| LDAP 绑定密码 | 机密不经过模型上下文 |
| 登录 / 登出 / 设备授权确认 | 授权必须由人在浏览器完成，Agent 不能替自己授权 |

### 5.5 管理模式

- 有管理权限的人在「我的令牌」里对某个令牌点「开启管理模式」，选 1 小时 / 8 小时，**需要再输一次密码**（LDAP 用户输 LDAP 密码）。
- 也可以在 DSH 里让 Agent 发起：Agent 给出一个链接，管理员在浏览器里确认开启。Agent 自己无法开启。
- 开启期间该令牌对应的 DSH 出现管理工具；到期自动消失，DSH 收到工具变更通知。
- 管理模式的开启、关闭、到期都写审计日志。

## 6. 功能三：Agent 当向导

### 6.1 员工向导

- **新人接入**：员工问「怎么开始用」，Agent 按企业设置介绍：有哪些模型、额度多少、能力中心有哪些推荐给本部门的能力，并帮他启用。
- **接入诊断**（`诊断`）：检查本机 `.npmrc`、DSH 登录状态、接入插件版本、模型连通、企业连接、必装插件；每一项给出 ✅ / ❌ 和修复建议，能自动修的（如补写 `.npmrc`、装缺的插件）在员工同意后执行。
- **按需推荐**：员工描述要做的事（「写周报」「查线上告警」），Agent 在能力中心里找有权限的技能、连接、微应用，说明区别并帮他启用；找不到时告诉他可以申请哪个连接或找谁。
- **分享引导**：对话里沉淀出好用的提示词或技能时，Agent 主动建议「要不要分享到能力中心」，帮他补齐标题、说明、可用范围，提交审核。

### 6.2 管理员向导

- **首次部署**：新部署时管理员说「帮我把系统配起来」，Agent 按清单逐项引导：站点地址 → 模型供应商 → 默认模型与额度 → LDAP（可选）→ 部门与角色 → 企业连接 → 发布接入插件 → 生成员工接入通知。每步都显示要做的变更，管理员确认后执行，已完成的项自动跳过。
- **日常巡检**：「今天有什么要处理的」→ 待审核数量、额度将耗尽的人、失败的上游同步、连接错误率。
- **审核助手**：读插件包文件列表、`package.json` 脚本、技能正文，标出可疑点（安装脚本、网络访问、外传数据），给出建议；结论由管理员确认。

## 8. 分阶段与验收

| 阶段 | 范围 | 验收标准（产品视角） |
|---|---|---|
| **A. 统一令牌** | 新令牌模型与能力范围、机器人账号、DSH 内登录、「我的令牌」与「令牌管理」、接入插件改用凭据库 | 新员工只运行一行命令 + 在浏览器点一次「授权」就能在 DSH 里用模型、技能、连接；吊销令牌后 DSH 提示重新登录；机器人令牌的用量单独统计、额度单独生效 |
| **B. 员工 Agent** | 工具框架、员工侧全部工具、诊断、员工向导技能、审计「经 Agent」 | 在真实 DSH 里用一句话完成：查额度、启用技能、把对话里的提示词分享到能力中心、申请连接；所有写操作都弹审批 |
| **C. 管理 Agent** | 管理模式、管理侧全部工具、危险操作两步确认 | 管理模式下用 Agent 完成：新建用户、设部门额度、审核通过一个技能、开关连接工具；未开启管理模式时看不到管理工具；危险操作不确认不执行 |
| **D. 向导** | 首次部署向导、日常巡检、审核助手、按需推荐 | 一套全新部署，管理员只和 Agent 对话就能配到员工可接入 |

## 9. 成功指标

- 新员工从拿到命令到第一次成功调用模型：≤ 3 分钟，且不需要看文档。
- 接入相关的支持工单下降（以诊断工具的使用量与修复成功率衡量）。
- 能力中心的分享量：经 Agent 提交的技能 / 提示词占比。
- 机器人令牌覆盖：团队共用 / CI 的用量从个人令牌迁到机器人令牌。
- 安全：Agent 来源的危险操作 100% 有确认记录；零起越权（令牌权限超出账号）的事件。

## 10. 风险

| 风险 | 对策 |
|---|---|
| 员工电脑上的令牌泄露 | 令牌存本机凭据库而非 `.env`；默认不带管理范围；管理模式限时 + 需要密码；按设备吊销 |
| 模型被提示注入诱导执行操作（如网页内容让它吊销令牌） | 写操作一律 DSH 审批；危险操作服务端两步确认；Agent 无法开启管理模式、无法替自己授权 |
| 工具太多挤占模型上下文 | 按领域合并工具、按权限裁剪；员工约 15 个、管理员约 40 个以内 |
