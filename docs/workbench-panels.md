# 业务工作台面板设计（2026-11-05）

## 想要的效果

每个微应用打开后，不只是一个对话框，而是一个**针对这项业务的工作台**：左边是对话，右边是这项业务的面板，比如报销助手的面板上有「待我审批」表格、「本月报销」指标、「新建报销」表单，以及费控系统的网页。员工可以直接在面板上点按钮让 AI 去办，AI 办完把结果写回面板。

```
┌────────────┬───────────────────────────┬──────────────────────────────┐
│ DSH 侧栏    │ 对话（这个应用绑定的会话）    │ 业务面板（右侧栏，可拖宽/全屏） │
│            │                           │ ┌ 报销工作台 ┬ 费控系统 ┐      │
│ 企业应用    │  /expense-helper           │ │ 本月已报 3,200  待审 4  │      │
│  🧾 报销助手 │  …                        │ │ 待我审批（表格）[让 AI 审核]│      │
│  📦 采购    │                           │ │ 新建报销（表单）[交给 AI]  │      │
│            │                           │ │ AI 看板：本轮处理结果      │      │
└────────────┴───────────────────────────┴──────────────────────────────┘
```

## 和 dsh-worktable 的区别

dsh-worktable 做的是同一类事：项目打开后，左边是内容窗口，右边是对话。但它是自己画一层浮层，再靠调整页边距把官方对话区挤开，依赖页面结构，所以只能把版本卡死，而且只测过 Windows。

DSH 0.2 的**官方右侧栏**已经是一个完整的停靠系统（`@deepseek-ai/dsh-client-ui-sidebar-right`）：

- 每个会话有自己的一套布局（标签页、左右分栏、浮动窗口、拖宽、全屏），保存在 `dsh.sidebar-right.v1.<sessionId>`，刷新后自动恢复；
- 插件可以注册自己的标签页类型：`ctx.sidebarRightTabs.register(...)` 注册类型，再用 `ctx.slots.register({ name: 'sidebar.right.pane.tab', key })` 提供内容组件；
- 插件可以用 `ctx.sidebarRight.openTab` / `openResource` 打开标签页，用 `split()` 分栏，用 `toggleFullscreen()` 切全屏；
- 官方「浏览器」标签页可以直接打开网址：`ctx.sidebarRight.openTab('browser', { params: { url } })`。Desktop 里它是独立的 webview，内部系统的登录状态由它自己保存；web profile 默认关着，需要在接入插件的配置补丁里打开（和关掉 `ui-brand-official` 用的是同一种写法）。

我们的企业面板已经在用这套机制，证明它能用。所以业务工作台**全部建在官方右侧栏上**，不画浮层，不碰页面结构。应用和会话已经绑定（第二轮的 W3），而右侧栏布局按会话保存，所以每个应用回到自己的会话时，工作台布局也会跟着回来。

官方右侧栏有两个限制：会话没开始之前（新对话首屏）右侧栏是空的；停靠区最多分成两栏（再多的内容放在标签页或浮动窗口里）。对我们的使用方式都不构成问题。

## 面板里有什么

管理员在 dsh-ee 网页上编辑微应用时，多一项「工作台」配置，不需要写代码。工作台由若干个**窗格**组成，每个窗格是右侧栏里的一个标签页：

| 窗格类型 | 内容 |
|---|---|
| `panel` 业务面板 | 由下面几种组件从上到下排列，接入插件自己画 |
| `web` 网页 | 用官方浏览器标签页打开一个内部系统的网址 |

业务面板的组件（第一版只做这六种）：

| 组件 | 数据从哪来 | 用户能做什么 |
|---|---|---|
| `metric` 指标卡 | 调一个**只读**的企业连接工具，取返回结果里的一个字段 | 看；点刷新 |
| `table` 表格 | 调一个**只读**的企业连接工具，取返回结果里的列表 | 每行可以有几个按钮，点按钮把一段带这一行数据的话发给 AI |
| `form` 表单 | 管理员定义字段 | 填完点提交，把填写内容拼成一段话发给 AI |
| `actions` 快捷按钮 | — | 每个按钮是一段固定的话，点了发给 AI |
| `markdown` 说明 | 管理员写的文字 | 看 |
| `board` AI 看板 | AI 通过一个工具写进来 | 看 AI 本轮的处理结果（表格、清单、要点） |

几条原则：

1. **面板上的按钮不会直接改业务数据**，只会把一段话发给 AI。AI 再用企业连接里的工具去办，写操作照旧经过审批卡。这样所有写操作都在对话记录和审计日志里，跟「Agent 写操作要审批」的既定做法一致。
2. **面板自动取数只能用只读工具**（`connection_tools.read_only`）。网页上保存配置时就要校验，接入插件取数时再校验一次。取数走现有的企业连接网关，所以权限、审计、工具级授权都会生效：员工没有权限的工具，对应组件显示「无权限」。
3. **AI 看板是 AI 往面板写东西的唯一通道**。接入插件注册一个本机工具（类似现有的 `ee_plugins.upload`），AI 调用它把结果写进当前会话的看板。这个调用在对话记录里看得到，符合上游「模型能看到的东西都要有记录」的规则。
4. **AI 知道面板的存在**。`/名字` 加载的微应用指令里多一节「工作台」，说明面板上有哪些组件、按钮发来的话是什么格式、什么时候该更新看板。

## 配置长什么样

存在微应用版本内容（`assetSpec`）里，跟人设、示例问题一起审核、一起出版本：

```json
"workbench": {
  "panes": [
    {
      "type": "panel", "id": "main", "title": "报销工作台",
      "widgets": [
        { "type": "metric", "title": "本月已报", "source": { "connection": "expense", "tool": "month_summary" }, "field": "total", "format": "money" },
        { "type": "table", "title": "待我审批",
          "source": { "connection": "expense", "tool": "list_pending", "args": { "limit": 20 } },
          "rows": "items",
          "columns": [ { "field": "id", "title": "单号" }, { "field": "applicant", "title": "申请人" }, { "field": "amount", "title": "金额", "format": "money" } ],
          "row_actions": [ { "label": "让 AI 审核", "prompt": "审核报销单 {{row.id}}（申请人 {{row.applicant}}，金额 {{row.amount}}），给出是否通过和理由" } ] },
        { "type": "form", "title": "新建报销",
          "fields": [ { "name": "amount", "label": "金额", "kind": "number", "required": true }, { "name": "reason", "label": "事由", "kind": "text" } ],
          "submit": { "label": "交给 AI 填单", "prompt": "帮我新建一张报销单：金额 {{form.amount}}，事由 {{form.reason}}" } },
        { "type": "board", "title": "AI 看板" }
      ]
    },
    { "type": "web", "id": "erp", "title": "费控系统", "url": "https://fk.example.com/" }
  ]
}
```

`{{row.x}}`、`{{form.x}}` 只做简单的文字替换，替换出来的就是发给 AI 的一段普通文字，不会被当成命令执行。

## 打开工作台的流程

1. 员工在侧栏点开一个带工作台的应用：照第二轮的规则新建或回到会话。
2. 会话切过去以后，接入插件在这个会话的右侧栏打开工作台：第一个窗格占主区；第二个窗格优先另开一栏（`preferNewPane`），放不下就作为同一栏的另一个标签页。
3. 回到已经打开过工作台的会话时，官方右侧栏会自己恢复布局，插件不重复打开；员工自己关掉的窗格也不强行重开。应用卡片的「⋯」里有「打开工作台」可以手动重开。
4. 没有配置工作台的应用，行为和现在一样。

## 不在第一版里

- 管理员可视化拖拽搭建面板：第一版是在网页上编辑 JSON，带校验、示例模板和预览。
- 面板直接调用写工具（跳过 AI）。
- 自定义 HTML 面板或第三方前端组件；需要复杂界面的业务，先用 `web` 窗格嵌入已有系统。
- 面板之间联动（点表格某一行，另一个组件跟着变）。
- 跨设备同步面板布局（官方右侧栏本身就不同步）。
