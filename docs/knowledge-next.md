# 知识库第二期方案：检索工具、文档格式、产品体验（草案，2026-11-09）

> 状态：方案已确认，待实现。2026-11-09 定：OCR 先不做（见 §9），所以也不需要后台入库，转换照旧在上传时同步完成；`.doc` / `.xls` 不支持；Excel 上限 5 万行；`.pptx` 做（见 §7）。第一期的设计和实现见 [knowledge.md](knowledge.md)，本文只写第二期要改的地方。
> 不少做法参考了腾讯开源的 WeKnora（MIT），对应位置列在 §10。只借鉴做法，不引入它的代码和服务。

## 1. 范围

1. **检索工具改进**：正则检索先走索引、搜索时顺带匹配标题、能限定在几篇文档里搜、能在单篇文档里查词。
2. **Word**：自动编号（条款号）、合并单元格。
3. **PDF**：逐页判断有没有文字层、识别乱码、去掉每页都重复的页眉页脚。
4. **Excel / CSV / PPT**：新增支持。
5. **产品与体验**：文档好读、上传时就知道转换得好不好、维护者知道该补什么、员工看到的界面里没有技术术语（§5）。

不变的：上传时同步转换；不用向量；`CGO_ENABLED=0` 单个二进制；正文是带行号的 Markdown，引用核对（`kb__verify`）和原文窗格的做法不变；权限只到知识库这一级。

## 2. 原则

- **默认什么都不用装**。Word、PDF 文字层、Excel、CSV 全部纯 Go 解析，装好就能用。
- **转得不对，维护者能改**。转换结果仍是 Markdown，网页上可以直接改（第一期已有）。
- **少加依赖**。新增的第三方库只有 excelize（BSD-3）和 golang.org/x/text（BSD）。

## 3. 检索工具改进

都只改 `kb/index.go` 和 `api/knowledge_tools.go`，不加表。

| # | 改动 | 现在 | 改后 |
|---|---|---|---|
| R1 | `kb__search` 的 `regex` 模式先走索引 | 对所有有权限的段整段逐行扫；正则写错就报错 | 从正则里提取字面词（`第\d+条` 提出「第」「条」，`差旅\|出差` 提出「差旅」「出差」），先用索引找出候选段，再逐行用正则核对。提不出字面词时退回逐行扫，照旧有超时和条数上限。正则写错就当普通文字匹配，结果里说明一句 |
| R2 | 搜索时顺带匹配标题 | 只搜正文；要找某篇文档得先 `kb__browse` | 同时按文档标题和文件名匹配，结果里多一个 `docs` 列表：「名字对得上的文档」（最多 5 篇，带编号、行数）。员工问「差旅管理办法里怎么说」，一次就能找到那篇 |
| R3 | `kb__search` 加 `docs` 参数 | 只能限定知识库和目录 | 可以传 1～20 个文档编号，在召回之前就过滤掉其它文档。无权限或不存在的编号直接报错，不会悄悄退回全库检索 |
| R4 | `kb__read` 加 `query` 参数 | 只能按行号或标题读 | 在这篇里找同时含有所有关键词的段，返回这些段，每段前后各带 5 行上下文，最多 20 处。用于长文档里定位，省 token |

工具说明也要相应改一下：`search` 的说明里写「找某篇文档时直接搜标题」，`read` 的说明里写「长文档先用 query 定位再按行读」。

## 4. 文档格式

### 4.1 现状

| 格式 | 现在 | 主要问题 |
|---|---|---|
| `.docx` | 标题样式转 `#`，表格转 Markdown 表格 | **自动编号丢失**：制度文件里的「第一章」「第三条」「3.2.1」多半是 Word 自动编号，不在正文文字里，转出来就没了，员工问「第十二条」查不到；合并单元格变成空格子 |
| `.pdf` | 用 ledongthuc/pdf 按行抽文字层，每页加「## 第 N 页」 | 扫描件整份拒收；ToUnicode 映射不全的中文 PDF 会抽出乱码，却被当成正常文本收下；每页的页眉页脚混在正文里，干扰检索 |
| `.xlsx` `.csv` | 不支持 | 价目表、通讯录、FAQ 清单很常见 |
| `.doc` `.xls` | 拒收，提示另存为新格式 | — |

### 4.2 Word

- **自动编号**：读 `word/numbering.xml`，按每个段落的 `numId` / `ilvl` 维护计数器，把编号文字算出来补到段首。要支持的编号格式：`decimal`、`chineseCounting`（一、二、三）、`chineseCountingThousand`、`ideographTraditional`（甲乙丙）、`upperLetter` / `lowerLetter`、`upperRoman` / `lowerRoman`，还有 `lvlText` 里的模板（`第%1条`、`%1.%2.%3`）。遇到不认识的格式，退回成阿拉伯数字。带编号的标题样式（「第三章 差旅」）编号也补进 `#` 标题，这样标题路径和 `section` 读取都能用上。
- **合并单元格**：横向合并（`gridSpan`）照列数补空格子；纵向合并（`vMerge`）把上面格子的内容复制下来。这样每一行单独看都是完整的，搜到某一行时不会缺上下文。
- **不改的**：页眉页脚、批注本来就不读，继续不读；修订记录取接受修订后的文字（现在已经是这样）。脚注先不做。
- `.doc` 不支持，继续提示另存为 `.docx`（§7）。

### 4.3 PDF

- **逐页判断**：每页单独分成三类：
  - **文字页**：文字层正常，照旧抽；
  - **扫描页**：文字少于 20 个字，而且页面上有大图；
  - **乱码页**：有文字，但乱码字符占比超过 30%（私用区字符、替换符 `�`，还有单字频率异常，例如一页里大半是同几个生僻字）。
  扫描页和乱码页不收文字，在正文里占位：「第 N 页是扫描页（或文字无法识别），没有收录，请看原件」。这样整份文件不会因为几页扫描页被整份拒收，模型读到这里也知道这一页缺了。全部页都识别不了时还是拒收，提示「扫描件暂不支持」。乱码页如果不剔掉会污染检索，这是这一项最主要的收益。上传结果里告诉维护者哪几页没收录。
- **页眉页脚**：统计每页最上面两行和最下面两行，在超过一半页面里重复出现的（数字统一换成 `#` 之后再比，这样「第 3 页 / 共 20 页」也能认出来）就去掉。
- **表格和多栏**：不做版面分析，这是纯 Go 方案的上限。版面复杂的 PDF，维护者可以在网页上修正 Markdown。
- 每页的「## 第 N 页」保留，引用时能说清在哪一页。

### 4.4 Excel / CSV（新增）

用 excelize 读 `.xlsx`；`.csv` 先探测编码（UTF-8 / GBK / GB18030，Excel 导出的中文 CSV 多是 GBK），再按逗号、制表符或分号拆分。

- **结构**：每个工作表一节 `# <工作表名>`，表格按 100 行一段，每段一个小标题 `## 第 1～100 行`，**每段开头重复表头**。这样每一段单独被搜到、被读到时都带着列名。
- **单元格的值**：取 Excel 里显示的值（比如 `61.12%`、`2026-03-01`，而不是 `0.6112`、`46082`）；公式取缓存的计算结果；合并单元格的值复制到合并区域的每一格；隐藏的工作表跳过；全空的行和列去掉。
- **表头**：默认把第一行当表头。如果第一行像数据（比如大半是数字，或者和第二行类型一样），就改用 A / B / C 当列名。维护者可以在文档页面上改成「第一行是表头 / 不是表头」，改完重新转换。
- **搜索片段带上表头**：命中的行是表格行时，`kb__search` 的片段前面加上这一段的表头行，模型不用再读一次就知道每列是什么。
- **上限**：单个文件最多 5 万行、转换后的 Markdown 不超过 8 MB（这是第一期 `maxKBMarkdown` 的上限），超了就拒收，提示拆成几份上传。
- `.xls` 不支持，继续提示另存为 `.xlsx`（§7）。

### 4.5 PPT

`.pptx` 也是 zip 里装 XML，纯 Go 按页抽取：每页一节「## 第 N 页 <这页的标题>」，正文按文本框从上到下、从左到右排；表格转成 Markdown 表格；备注（讲者笔记）放在这一页最后，标「备注：」。图片、图表、SmartArt 不收。`.ppt` 不支持。

## 5. 产品与体验

### 5.1 现在的问题

我对着现在的代码走了一遍维护者和员工的流程，问题集中在下面这些地方：

| 地方 | 现在 | 问题 |
|---|---|---|
| 文档页（`knowledge-doc.tsx`）和 DSH 原文窗格（`kbDocView`） | 等宽字体显示 Markdown 源码，左侧带行号 | 像在看代码。表格是一串 `\|`，到了 Excel 文档会更难读；`# ##` 这些标记直接露在外面 |
| 上传（`UploadDialog`） | 弹窗里选文件、选目录，传完弹一句「成功 N 个，失败 M 个」 | 不知道转得好不好（丢了哪几页、表格对不对）；不能拖放；同名文件总是**新建一篇**，制度每年更新一次，库里就会堆满重复、过时的文档，模型也会读到旧版本 |
| 文档列表 | 表格：标题、目录、行数、版本、更新时间；目录用下拉框选 | 看不出文件类型和转换状况；没有目录树；只能按标题筛选 |
| 检索记录 | 按时间列出每一次检索（工具名、检索词、命中数） | 是流水账。维护者真正想知道的是「大家想查却查不到的是什么」 |
| 员工的 `/knowledge` | 知识库卡片，加一张「我的查询记录」表（工具名、检索词） | 员工看到的是 `search`、`read` 这些工具名，像后台日志；没有引导去 DSH 里提问 |
| 空状态 | 一句「还没有知识库」 | 第一次用的人不知道下一步做什么 |

### 5.2 要做的

按影响大小排序。X1、X2 跟着 P2 一起做，因为新格式转出来的结果得能看清楚；其它的放到 P4。

**X1 阅读视图（网页文档页和 DSH 原文窗格共用）**

- 文档默认用「阅读」视图：标题、列表、表格、引用块正常渲染，正文用正文字体。右上角可以切换到「原文」视图，也就是现在这种带行号的源码。
- 行号不丢：阅读视图里，每个段落、每一行表格都记着自己在原文里的起止行，鼠标移上去时在左边显示行号，`#L40` 这类链接照样能跳。
- 引用高亮：被引用的段落左边加一条品牌色竖线，摘句那几个字用 `<mark>` 精确标出来，打开时自动滚到这里。只有对不上的引用才退回整段高亮。
- 不同格式的样子：
  - PDF：每页之间加一条细分隔线，上面标「第 N 页」；未收录的页显示一张灰色占位卡：「第 N 页是扫描页，没有收录 · 下载原件查看」。
  - Excel：顶部按工作表切换；表格表头固定，隔行浅底色，可以横向滚动，数字列右对齐；「第 1～100 行」这种分段标题显示成浅色小字。
  - PPT：每页显示成一张卡片，标题加粗，「备注」用浅色字。
- 左侧是大纲，滚动时跟着高亮当前所在的位置；文档短于 3 个标题时不显示大纲。
- 渲染器自己写，不引入 Markdown 库，因为我们只需要渲染自己转换器产出的那部分语法（标题、段落、列表、表格、引用块、粗体、行内代码、链接）。这样「段落 ↔ 行号」的对应关系完全可控。维护者手改时写了别的语法，就按普通文字显示，不会出错。
- 代码放在 `dsh-plugin/src/kb-doc-render.ts`，网页通过已有的 `@workbench` 别名引用，跟工作台面板的渲染是同一种共用方式。50000 行的表格只渲染看得见的部分，按分段懒加载。

**X2 上传：拖进来就知道转得怎么样**

- 文档列表整块区域都可以拖放文件或文件夹，支持一次拖多个；「上传」按钮还在。区域里写清支持的格式：PDF、Word、Excel、CSV、PPT、Markdown、纯文本，单个文件不超过 50 MB。
- 每个文件一行进度，转换完给一张「转换体检」小卡，只说跟员工能不能查到有关的事：
  - ✔「收录 18 页 · 补回 46 个条款编号 · 3 个表格」
  - ⚠「第 3、7 页是扫描页，没有收录」「第 12 页文字是乱码，没有收录」「去掉了每页重复的页眉页脚」
  - ℹ「2 个工作表，隐藏的 1 个已跳过 · 第一行当作表头 [改]」
  - 每张卡上都有「预览」，直接打开阅读视图。
- 失败的原因要能照着做：`.doc` →「请在 Word 里另存为 .docx 再上传」；加密 PDF →「请去掉密码」；全是扫描页 →「这份是扫描件，暂不支持；如果有电子版请传电子版」；超过 5 万行 →「请拆成几份」。
- **同名文件**：同一个目录下已经有标题相同的文档时，默认「更新为新版本」（保留旧版本和历史引用，旧引用打开时提示「原文已更新」，这是第一期就有的），也可以选「另存为一篇」。一次传多个时，在一张确认表里逐个选。
- 体检信息记在文档上（`kb_docs` 加一个 JSON 列 `convert_info`，迁移 `0021_kb_convert_info.sql`）。文档列表和文档页都能看到，以后换了转换规则重新转换时也会更新。

**X3 文档列表**

- 每篇文档前面加文件类型图标，按类型用不同颜色（PDF、Word、Excel、PPT、Markdown）。标题下面一行小字：原文件名 · 更新时间 · 更新人。
- 状态标签只在有事时出现：「2 页未收录」「手工改过」「近 30 天被引用 12 次」。
- 左侧换成目录树，代替现在的下拉框：显示每个目录的文档数，可以拖动文档换目录。
- 筛选框可以选「搜标题 / 搜内容」：搜内容直接走同一个索引，结果按文档聚合，每篇下面列命中的几行。
- 可以批量勾选，然后移动、删除。

**X4 「待补文档」代替检索流水**

- 维护者的「检索情况」页，最上面是**没查到的**：把最近 30 天命中 0 的检索按词聚合，例如「年假 跨年 — 9 次，6 人」。每条后面有两个按钮：「上传文档补上」，以及「忽略」（这是库外的问题）。
- 下面是**常被读的文档**（`kb__popular` 已有）。原来的流水移到最下面并默认折叠，`audit.view` 的人才能看到是谁查的。
- 知识库卡片和导航上显示待补数量的小红点，例如「待补 3」。

**X5 员工视角的 `/knowledge`**

- 顶部是一个大搜索框「搜制度、手册、文档……」，搜标题和内容，结果直接打开阅读视图。旁边有一个按钮「在 DSH 里问」，用的是已有的唤起链接。
- 知识库卡片：图标、名字、一句话说明、文档数，加上**最近更新的 3 篇**（员工最关心的是「什么制度改了」）。
- 「我的查询记录」改名「我的检索记录」，默认折叠；里面把工具名翻成人话：「搜了：住宿 标准」「读了：差旅管理办法 第 40～72 行」。

**X6 第一次用**

- 一个知识库都没有时，显示三步引导：① 建一个知识库 ② 拖几份文档进来 ③ 在 DSH 里打开「知识问答」问一句。旁边放一个「导入星河科技示例制度」按钮（复用一键导入示例）。
- 知识库里有文档、但还没有应用用它时，在库页顶部提示「用这个库做问答应用」（`studio.makeAppFromKB` 已有，只是挪到更显眼的地方）。

**X7 编辑正文**

- 现在是一个大文本框。改成左右分栏：左边编辑 Markdown，右边实时显示阅读视图。
- 保存前显示改动对比，并提示「这次修改会让 N 条已有引用显示『原文已更新』」，让维护者知道改正文是有影响的。

**X8 DSH 里的「答案与出处」**

- 引用编号统一用小圆角标签：✔ 绿色、对不上红色、原文已更新灰色；鼠标移上去预览摘句和文档名，点开在原文窗格里显示阅读视图（X1）。
- 引用的内容落在未收录的页附近时（比如答案依据的是第 6 页，而第 7 页没收录），标签旁边加一个小提示「附近有未收录的页」。

### 5.3 统一的规矩

- **只用现有组件**：`components/ui.tsx` 里的 `Card`、`Badge`、`Segmented`、`Button` 和 shadcn 组件，颜色用品牌色变量 `brand-*`，不引入新的 UI 库。暗色模式和中英文（`i18n/zh`、`i18n/en`）每个新界面都要有。
- **员工能看到的文字里不出现技术词**：`kb__search`、「行号」「Markdown」「索引」只出现在维护者的「原文」视图和帮助说明里。员工看到的是「搜了」「读了」「第 40～72 行」「原件」。
- **每条提示都告诉人下一步做什么**：不写「转换失败」，写「请另存为 .docx 再上传」。
- **DSH 侧栏很窄**（约 360～480 px）：原文窗格和看板先按窄屏设计，表格横向滚动，大纲在窄屏下收成一个下拉框。
- **键盘**：文档页 `j`/`k` 跳到上一处或下一处高亮，`/` 聚焦搜索框，`Esc` 关闭弹窗；所有按钮都有焦点样式。
- **验收用截图**：每个界面在 `docs/images/kb-v2/` 留亮色、暗色、DSH 窄屏各一张截图，自测清单写在 `docs/knowledge-verify.md`（照 `nav-verify.md` 的格式）。

## 6. 测试

- 在 `server/internal/kb/testdata/` 放一组小样本。都用脚本生成，不放企业的真实文件：带自动编号的中文 docx、带纵向合并单元格的 docx、带合并单元格和百分比的 xlsx、GBK 编码的 csv、含一页扫描页的 PDF、ToUnicode 映射缺失的 PDF、每页都有页眉页脚的 PDF、带表格和备注的 pptx。每个样本配一份期望转出的 Markdown，做对比测试。
- 阅读视图渲染器：每种块（标题、列表、表格、PDF 分页、未收录占位）都对得上原文行号；摘句跨行、跨表格单元格时也能精确高亮；渲染不认识的语法时不出错。同名上传：默认更新、选择另存、多文件混合三种情况。
- 检索工具 R1～R4 各补单元测试。另外跑一下 10 万段规模的基准，确认 R1 在常见正则下明显比现在快。

## 9. 以后：OCR（这一期不做）

2026-11-09 定：先不做 OCR，保持轻量。以后要做时的思路（调研时记下的，不是承诺）：

- 不内置识别引擎（Tesseract、PaddleOCR 都要 CGO 或外部程序）；改为调企业已经配好的视觉模型（经 dsh-ee 模型网关），或者企业自己部署的文档解析服务（MinerU / PaddleOCR-VL，WeKnora 在 `internal/infrastructure/docparser/` 里接了这两种）。
- OCR 一页要几秒到几十秒，到时候得先把上传改成后台处理（排队、进度、重试）。
- §4.3 已经把扫描页和乱码页标出来了，以后 OCR 只要处理这些页。
