## 0. 准备

1. `git pull`，确认 `git log --oneline -1` 是 `9969790` 或更新。
2. `make build`，用单文件 `dist/dsh-ee` 起一个测试服务（独立数据库）。
3. 跑演示数据：`cd server && DSH_EE_API=<测试服务地址> DSH_EE_SEED_ADMIN_PASSWORD=<管理员密码> go run ./cmd/seed`，输出里应有：
   - `连接  + ee-catalog（企业插件目录，只读）`
   - `微应用 + plugin-guide（插件导购，带业务工作台）`
4. 想让表格里有数据，就先上架一两个插件（能力中心 → 上传 .tgz，或照 README 预载）。不上架也行，表格会显示「暂无数据」，指标显示 0。
5. 系统设置里发布接入插件（或者等后台检查自动发布）。因为「插件导购」有网页窗格，新版接入插件的 `cordis.patch.yml` 末尾应该有：
   ```yaml
   - id: ui-sidebar-browser
     disabled: false
   ```
6. 用一个演示员工（例如 `zhang.wei`）在**隔离的** `DSH_HOME` 里装上新版接入插件并登录，web profile 和 Desktop 各一套。

## 5. 最可能出问题的地方

如果 V1 或 V6 不通过，最可能的原因是下面几处，报错信息能帮我快速定位：

- 标签页类型的 `patterns: ['dsh-resource://dsh-ee-workbench/**']` 没匹配上地址（控制台可能有「no type claims」之类的报错）。
- `sidebarRight.mounted` 在新建会话后迟迟不变：我等 5 秒，超时就不打开工作台，也不报错。这时用「⋯ → 打开工作台」能不能打开，是区分原因的关键。
- `openTab('browser')` 在 web profile 没生效：先确认第 0 步第 5 条的补丁行确实在装好的插件里。
- 看板不更新：看 `$DSH_HOME/dsh-ee/boards/` 下有没有文件、文件名里的会话 id 对不对。

## 7. 第一版 M12：从 DSH 打开网页免登录（2026-11-07）

## 8. 第一版 M13：应用自带数据（2026-11-07）

应用可以在定义里声明 `tables`（几张小表），数据存在 dsh-ee。工作台的数据源写 `{"table": …}`（服务端在目录里换成 `app__rows` 调用），表单的 `submit` 写 `{"table": …}` 直接插入一行；模型用 `app__rows` 查（`group_by` 做统计）、用 `app__write` 写，删除要先拿预览、带确认码再执行（插件的审批框也会弹）。示例公司里的「团建报名」（`team-outing`）就是这样做的。

## 12. 第一版 M6 / M8 / M9：启动台与「工作台」、反馈、`/ee-save`（2026-11-08）

**M6 启动台与「工作台」系统应用**：工作台组件加 `"home": true`（每应用最多 2 个、只限带数据源的 metric / table / chart / checklist，保存时校验）会上到首屏的「需要你处理」和系统应用「工作台」（`/workbench`）的「我的待办」窗格；「工作台」右侧还有我的应用（`home__apps`）、本月用量（`home__usage`）、新上线（`home__new`）三个窗格，左边对话是「总助理」。目录里应用多了 `new`（近 14 天上线）和 `todo`（首页组件数）两个标记，DSH 首屏「企业应用」菜单点开是铺开的卡片区（问候行 + 最多 8 张应用卡 + 轮换示例问题）。「最近会话」因为服务端拿不到 DSH 会话，换成了「新上线」。

**M8 反馈与答不上来的问题**：每条助手消息尾的 👍👎（`conversation.chat.assistant-actions` 槽位；没有该槽位的旧宿主直接不出按钮，看板文字反馈是备选方案）打到 `POST /api/dsh/feedback`，带会话绑定的应用、消息 id 和 👎 时的可选原因。应用详情显示反馈汇总（👍/👎/近 30 天）和「答不上来的问题」——👎、app__ 工具报错、kb 检索为空三类信号按归一化文本合并计数，只有问题文本和次数，看不到是谁。

**M9 `/ee-save`**：DSH 里 `/ee-save` 把提炼请求作为消息发进当前会话（模型本来就有全文），模型先建议类型（提示词 / 技能 / 应用）、员工确认后用 `ee_hub` `for_me` 建好并给网页链接；说明里注明来自一次对话。「我分享的能力被多少人用」沿用 ee_me overview 的 contributions。
