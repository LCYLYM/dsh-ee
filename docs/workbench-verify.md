## 0. 准备

1. `git pull`，确认 `git log --oneline -1` 是 `9969790` 或更新。
2. `make build`，用单文件 `dist/dsh-ee` 起一个测试服务（独立数据库）。
3. 跑演示数据：`cd server && DSH_EE_API=<测试服务地址> DSH_EE_SEED_ADMIN_PASSWORD=<管理员密码> go run ./cmd/seed`，输出里应有：
   - `连接  + ee-catalog（企业插件目录，只读）`
   - `微应用 + plugin-guide（插件导购，带业务工作台）`
4. 想让表格里有数据，就先上架一两个插件（能力中心 → 上传 .tgz，或照 README 预载）。不上架也行，表格会显示「暂无数据」，指标显示 0。
5. 系统设置里发布接入插件（或者等后台检查自动发布）。因为「插件导购」有网页窗格，新版接入插件的 `cordis.patch.yml` 末尾应该有：
   ```yaml
   - id: ui-sidebar-browser
     disabled: false
   ```
6. 用一个演示员工（例如 `zhang.wei`）在**隔离的** `DSH_HOME` 里装上新版接入插件并登录，web profile 和 Desktop 各一套。

## 4. 升级路径

1. 先装**升级前**的接入插件（例如 `a04d14c` 时代生成的版本），再把服务端升级到本版。
2. 确认后台检查自动发布了新版接入插件，`/dsh-ee-doctor` 提示有新版本。
3. 按提示升级（web 和 Desktop 各一次；tarball 安装的插件可能要先卸载再添加，以实测为准），记下实际用的命令。

## 5. 最可能出问题的地方

如果 V1 或 V6 不通过，最可能的原因是下面几处，报错信息能帮我快速定位：

- 标签页类型的 `patterns: ['dsh-resource://dsh-ee-workbench/**']` 没匹配上地址（控制台可能有「no type claims」之类的报错）。
- `sidebarRight.mounted` 在新建会话后迟迟不变：我等 5 秒，超时就不打开工作台，也不报错。这时用「⋯ → 打开工作台」能不能打开，是区分原因的关键。
- `openTab('browser')` 在 web profile 没生效：先确认第 0 步第 5 条的补丁行确实在装好的插件里。
- 看板不更新：看 `$DSH_HOME/dsh-ee/boards/` 下有没有文件、文件名里的会话 id 对不对。
